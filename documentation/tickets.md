# Tickets

All tickets live in the `tickets/` directory at the root of this repository. Planning and in-progress work are tracked in the GitHub project (the project board) that the team uses.

## Why tickets live in the code

The tickets are part of the codebase so that **every agent can see what everyone is working on**. Any coding agent or human that opens this repository has access to the full list of tickets, which keeps work visible and avoids duplication. Ticket changes go through the same pull-request flow as code, so what was agreed and why is preserved in the history.

## Where things live

| Thing | Location |
| --- | --- |
| Ticket definitions (the durable record) | `tickets/` at the repository root |
| Planning and tracking of in-progress work | The GitHub project board |

## Conventions

- New tickets go in `tickets/`.
- The GitHub project board is used to plan work and to follow what is in progress.
- Keep the tickets current so the board and the repository do not disagree about what is being worked on.
