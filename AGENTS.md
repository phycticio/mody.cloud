# AGENTS.md

## Project summary

Mody Cloud is a digital sovereignty service, run by its maintainer as a self-employed professional in Spain. Members define their brand identity once (a wizard; the brand then lives in each site's own WordPress settings and styles) and a sovereign AI agent generates every page of their WordPress site, faithful to that brand. The whole stack is European or Swiss. Every site costs the same (7.99 EUR a month or 79.99 a year, VAT included) and gets the same features (1 GB, every plugin in the market, its own Mody); the first 50 accounts get one site free for six months. Full context: [documentation/project-overview.md](documentation/project-overview.md).

This repository holds the platform. It has a Dockerized WordPress Multisite stack (Nginx, PHP-FPM, MariaDB, Redis, Mailpit), the Full Site Editing theme at `app/web/themes/theme`, and the platform's MU plugin at `app/web/mu-plugins/mody-platform/`. Production installs plugins only through Composer and `./bin/deploy`, because wp-admin file changes are disabled there.

**Built so far:**
- the brand wizard and site provisioning, with each site's brand in its own settings, design presets and fonts (M2);
- the AI agent: page generation and validation, the chat bubble in the editors, and tools for design, publishing and site settings (M3);
- member-site gating (M4, in progress);
- site languages: every site can have other languages, with translations as pages, `/es/` addresses, a switcher and the translation matrix (in progress, [tickets/site-languages.md](tickets/site-languages.md));
- the signup: a chat that creates the account, its first site (free for six months, the launch offer) without a card, then the editor tour (M1-03).
- The Mody dashboard: every site's Dashboard, with visitors (our own cookieless counter), Mody's tokens on design and configuration, the member's sites, Plan & billing; the space per site enforced (1 GB since 2026-11-13) ([tickets/mody-dashboard.md](tickets/mody-dashboard.md), 2026-11-11).
- Your brand: Settings → Brand, where the owner tells Mody about the business (voice, audience, offer, story, values, facts); every prompt reads it ([tickets/your-brand-page.md](tickets/your-brand-page.md), 2026-11-11).

**Not built yet:** billing (payments with Mollie, M1), and the production launch (M5). Status: [documentation/roadmap.md](documentation/roadmap.md). Next steps, in order: [tickets/next-steps.md](tickets/next-steps.md).

## Non-negotiable rules

Full text and consequences: [documentation/constraints.md](documentation/constraints.md).

1. **Absolute sovereignty.** Nothing from Cloudflare, OpenAI, Google AI, AWS or Azure. Data and traffic stay in Europe or Switzerland. A US service makes a solution invalid.
2. **Exact Gutenberg format.** Generated output is always serialized `<!-- wp:block -->` comments. Validate the inner JSON. See [ai-engine.md](documentation/ai-engine.md).
3. **Only FSE, Gutenberg and Spectra.** No Astra, no Elementor, no builders with lock-in. Styles through `theme.json`. See [theme-development.md](documentation/theme-development.md).
4. **Brand coherence.** Every generation injects the site's brand (its WordPress settings) into the system prompt. Never generate without brand context. See [brand-profile.md](documentation/brand-profile.md).
5. **Simplicity.** If something takes more than 2 hours, propose a simpler alternative. Finishing beats perfecting.
6. **Security.** Never expose credentials or WordPress Application Passwords. Only the web tier is public. Sanitize wizard inputs. See [architecture.md](documentation/architecture.md#invariants-that-carry-over-from-the-briefing).
7. **Honest plans.** Prices are the published plans, the same for everyone. Never write "unlimited": every limit is real (1 GB per site, Mody's tokens a month, the account's sites). See [membership-tiers.md](documentation/membership-tiers.md).
8. **Language.** Everything is in English: code, comments, documentation, commit messages, prompts to the model and agent replies. This overrides the briefing's Spanish convention.

## Decisions already made

- **Infrastructure is the current stack.** Do not adopt the briefing's Nginx Proxy Manager, its sample `docker-compose`, or Matomo. Why and what replaces them: [architecture.md](documentation/architecture.md#briefing-recommendations-not-adopted).
- **AI model:** `Qwen/Qwen3.8-27B-FP8` (project-scoped build) through Infomaniak AI Services (OpenAI-compatible, base URL `https://api.infomaniak.com/2/ai/{PRODUCT_ID}/openai/v1`). Decided 2026-11-01, superseding the briefing's Ministral choice. See [mvp-spec.md](documentation/mvp-spec.md) and [ai-engine.md](documentation/ai-engine.md).
- **AI integration: the WordPress AI Client, no Python service** (decided 2026-11-04). Models are called with core's `wp_ai_client_prompt()`. The Infomaniak provider lives in the MU plugin, and its configuration comes only from the environment (`INFOMANIAK_API_KEY`, `INFOMANIAK_AI_BASE_URL`). The agent's tool loop and validator run in PHP in the MU plugin. See [ai-engine.md](documentation/ai-engine.md).
- **Agent actions are WordPress abilities ("Option C", decided 2026-11-06).** They are registered in the `mody` category, and the in-site agent and MCP clients both call them. The site's brand also goes into the `ai` plugin's eight writing features (`wpai_system_instruction`, `src/AI/PluginBrandContext.php`; analysis features are left unchanged, decided 2026-11-06). M4 locks that plugin's settings, approvals and MCP on member sites. Its request log is the basis for per-member cost tracking. The first ability, `mody/generate-page`, saves validated drafts. See [mvp-spec.md](documentation/mvp-spec.md#8-the-agent) and [ai-engine.md](documentation/ai-engine.md#generating-a-page).
- **Generated layout is Spectra containers** (decided 2026-11-07). Every section, row and column the page writer builds is a `spectra/container` with fixed responsive settings (`AI\SpectraLayout`: sections, grid rows, columns), so pages are built the same way on every site. New pages may not use core group, columns or column. The theme's templates and parts use containers too (2026-11-08), and `post-content` is never inside one. See [ai-engine.md](documentation/ai-engine.md#layout-spectra-containers) and [theme-development.md](documentation/theme-development.md#structure).
- **Spectra is the platform's block library: a MU plugin, behind `SpectraGuard`** (network-active from 2026-11-06; a MU plugin since 2026-11-08, [M3-11](tickets/M3-11-spectra-mu-plugin-all-blocks.md)). Composer installs it into `app/web/mu-plugins/spectra-blocks/`, and `mu-plugins/spectra-blocks.php` loads it after `mody-platform.php`, so the guard is in place first. Nobody can switch it off. `Spectra\SpectraLoader` keeps the old network-activated copy from loading. The agent will use every Spectra block except the popup builder (M3-11, in parts): the validator accepts them since 2026-11-09 (`BlockValidator::SPECTRA_BLOCKS`), and the prompts learn them family by family. The guard in the MU plugin switches off everything in Spectra that connects outside Europe: the Google Map block, the AI design library, ZipWP, telemetry, Google Fonts, the dashboard's videos and nudges. It also refuses requests to those hosts, and pins Spectra's own abilities and MCP server off (weak permissions). If Mody uses those abilities, it is only behind its own `mody/*` abilities. After every Spectra update, run `scripts/spectra-guard-test.php`. The fork into our own `mody/*` blocks is set aside (decided 2026-11-08, [tickets/mody-blocks-from-spectra.md](tickets/mody-blocks-from-spectra.md)). See [mvp-spec.md §10](documentation/mvp-spec.md#10-plugin-market-and-capability-gating).
- **Plugins: no screen for anyone; Composer, deploy and WP-CLI only** (decided by the maintainer on 2026-11-11, [tickets/hide-plugins-and-connectors.md](tickets/hide-plugins-and-connectors.md); it replaces M4-02's "core's Plugins screen for members" of 2026-11-08). `Gating\HiddenScreens` removes the Plugins screens (site and network), Settings → Connectors and the `ai` plugin's connector approvals from every menu, refuses them by URL, refuses the plugin and block directory REST routes to everyone, keeps the connector keys (`connectors_*`) out of `/wp/v2/settings` for everyone and refuses the `ai` plugin's options (`wpai_*`) there to members. Super admins included; WP-CLI is not affected. Platform plugins (`Gating\MemberPlugins::PLATFORM_PLUGINS`) and network-active ones still never switch through another path. No plugin is offered to members yet. Check every plugin against rule 1 before adding it to Composer. See [mvp-spec.md §10](documentation/mvp-spec.md#10-plugin-market-and-capability-gating).
- **One profile per person, kept on the main site; no Gravatar** (decided by the maintainer on 2026-11-11, [tickets/network-profile-local-avatars.md](tickets/network-profile-local-avatars.md)). Every other site sends Profile and Edit User to the main site, and refuses profile changes over REST (user meta, such as the editor's preferences, still saves). Pictures are uploaded there and stored in the main site's media library (`Users\Avatars`); everyone else gets initials drawn by the platform. Nothing calls gravatar.com.
- **Embeds are the member's choice** (decided by the maintainer on 2026-11-11): rule 1 binds what the platform runs and loads by itself, not what a member puts on their own site. Core's embeds (YouTube, X and the others) stay available to members.
- **Nobody updates WordPress or a plugin from wp-admin** (decided 2026-11-08). Versions change only in the repository: core with `./bin/version`, plugins in `app/composer.json`. They reach production through `./bin/deploy`. `Gating\Updates` refuses the four update capabilities to every user, super admins included, on every environment. It also removes core's automatic update checks to WordPress.org. Wordfence's scans and WP-CLI still call them directly. See [tickets/updates-through-composer-only.md](tickets/updates-through-composer-only.md) and [mvp-spec.md §10](documentation/mvp-spec.md#10-plugin-market-and-capability-gating).
- **A site's brand is its own WordPress data; WordPress's settings and screens come first** (decided 2026-11-08, [M2-08](tickets/M2-08-brand-profile-wordpress-settings.md)).
  - **Identity:** name (the site title), tagline, logo and icon are WordPress settings, changed on the Identity screen (`site-editor.php?p=/identity`) or through `mody/update-site-settings` for words.
  - **Styles:** colors, fonts and every other style are the site's Global Styles (Editor → Styles).
  - **Mission and tone** are two site settings, `mody_mission` and `mody_tone` (`Brand\BrandSettings`). They are shown on the Identity screen (`assets/identity-fields.js`) and in Settings → General.
  - **No profile:** the `mody_brand_profiles` table was dropped, and prompts read the brand when they run.
  - **For every feature:** when WordPress has a setting or a screen for something, use it, and never keep a copy.
- **Your brand: the rest of the brand is one site setting, `mody_brand`** (decided by the maintainer on 2026-11-11, [tickets/your-brand-page.md](tickets/your-brand-page.md)). Settings → Brand (reached from the Identity screen) holds what WordPress has no place for: vision, voice, the form of "you", words to use and avoid, audience, products and services, story, values and facts. Administrators only; one brand per site, in any language; the agent saves what the owner tells it directly (the `brand_` settings of `mody/update-settings`). Every prompt reads the filled-in fields, and the writers use the real facts instead of placeholders.
- **Patterns are the Mody collection** (the design market, built 2026-11-08). Every site's patterns come from `mody-platform/patterns/collection.json`: 63 patterns rewritten from the WordPress.org Pattern Directory and core by `scripts/import-patterns.php` (`Design\PatternImport`).
  - **What the rewrite does:** palette slugs, the theme's fonts, the platform's own placeholder images (`/mody-placeholder/<w>x<h>.svg`), no links to other sites.
  - **Where they show:** on the Patterns screen and in the inserter.
  - **What is switched off:** the remote Pattern Directory and core's bundled patterns, and the Directory proxy is refused to members.
  - **Themes:** Mody is the only theme provider; which themes members see is tech debt.

  See [tickets/design-market-themes-patterns.md](tickets/design-market-themes-patterns.md).
- **The business and its price** (decided by the maintainer on 2026-11-10; the price per site and the launch offer on 2026-11-13, [tickets/pricing-per-site.md](tickets/pricing-per-site.md)). Mody Cloud is run by a self-employed professional in Spain, not a non-profit association: "fees equal real cost" is gone (rule 7 changed). **Every site costs the same: 7.99 EUR a month or 79.99 a year (ten months for twelve), VAT included**, with no discount for more sites (up to 10 per account). Every site gets the same: 1 GB, every plugin in the market, its own Mody that knows only that site (5,000,000 tokens a month, at most 1,000,000 a day, `Agent\Budget`), a custom domain (not built yet) and a way out. **The launch offer replaces the trial:** during the first three months, the first 50 accounts get one site free for six months, no card (`Members::start_free()`); after that the signup says the places are taken until paid signups open with Mollie. When the free months end: reminders a month and a week before, then read-only for 60 days without a card, then deletion (not built; it needs Mollie). See [membership-tiers.md](documentation/membership-tiers.md).
- **Payments:** Mollie (EU), decided 2026-11-01. A card before the free months end (0.01 EUR verification; it was "at signup" until 2026-11-08), then monthly or yearly billing per site; past-due sites read-only for 60 days before deletion. See [mvp-spec.md](documentation/mvp-spec.md#4-price-launch-offer-and-billing).
- **Signing up needs no card, and the signup is a chat** (decided by the maintainer on 2026-11-08, [M1-03](tickets/M1-03-chat-signup-and-editor-tour.md); the trial became the launch offer on 2026-11-13). `/register/` asks the visitor's name, email, project name and address one at a time; then the account, a place of the launch offer (six months free, one site) and the first site (a starter site: no model call) exist, and an email holds the set-password link. The first password logs the member in on their site's Identity screen, where the editor tour shows the agent, asks for two requests, then explains the Site Editor. The card comes before the free months end (M1-01 part 3, reworked). See [mvp-spec.md §4](documentation/mvp-spec.md#4-price-launch-offer-and-billing).
- **Platform logic lives in one MU plugin:** `app/web/mu-plugins/mody-platform/` (AI provider and agent, registration, billing, dashboard, provisioning, wizard, market, gating, editor redirects). See [mvp-spec.md](documentation/mvp-spec.md#12-architecture-deltas).
- **Composer dev requirements are intentionally only Query Monitor and User Switching** (User Switching 1.12.2 added at the maintainer's request on 2026-11-08, to act as another user locally; no outbound calls). Do not add dependencies (Composer or npm) without asking. See [architecture.md](documentation/architecture.md#current-stack-unchanged).
- **JS is built with `@wordpress/scripts`, and gets only the libraries it needs.** Sources live in `src/`, and `pnpm build` compiles them into `app/dist`. Use WordPress packages and the tooling wp-scripts already ships first. Add another library or framework only when a feature needs it and no WordPress package covers it, and record why in [theme-development.md](documentation/theme-development.md#rules). Bundle everything. Nothing loads from a CDN (rule 1).
- **Temporary exceptions to rule 1: Cloudflare, Wordfence and Brevo.** Cloudflare and Wordfence stay in production until Mody Cloud can afford to replace them (decided 2026-11-04). Do not add other US services, and do not use these two for anything new. The one exception (2026-11-08) is a Cloudflare API token for the wildcard certificate's DNS challenge (M5-02). Brevo sends production mail since 2026-11-09: the maintainer already pays for it, and an EU relay replaces it later. See [architecture.md](documentation/architecture.md#temporary-exceptions-to-rule-1).
- **Antibot: ALTCHA, run on our own servers** (decided by the maintainer on 2026-11-10, "option A", [tickets/antibot-altcha.md](tickets/antibot-altcha.md)). It is a proof-of-work check that calls no outside service: no reCAPTCHA, hCaptcha, Turnstile or Akismet. `Security\Altcha` signs and checks the challenges, with secrets from WordPress's salts, and accepts each solution once. The widget is the npm package `altcha` (pinned), bundled by `pnpm build` into `app/dist/altcha.js`. It guards the signup chat, login, lost password and visitors' comments on every site (`Security\FormGuard`).
  - **Antispam Bee** (2.11.13, added 2026-11-10) checks what people type in comments. Like Spectra, it is a MU plugin installed by Composer into `mu-plugins/antispam-bee/`, so nobody can switch it off. `Security\AntispamBee` pins its three checks that call outside services off: Gravatar, iplocate.io and its language API.
  - **Rate limit:** still an open question in the ticket.
- **Site languages: the `mody-languages` MU plugin** (decided by the maintainer on 2026-11-10, [tickets/site-languages.md](tickets/site-languages.md)). Our own plugin, not Polylang or another multilingual plugin, loaded on every site; the second exception to "platform logic lives in one MU plugin". A translation is an ordinary page with the post meta `mody_lang` and `mody_source`; pages without them are in the site's default language (core's Site Language). Other languages live under a prefix (`/es/…`), never a subdomain; the language comes only from the address (caches stay correct). Offered: English, Spanish, French, German, Italian, Portuguese, Dutch and Catalan. Mody's translations are saved as drafts. A site with one language behaves as without the plugin.
- **The Mody dashboard is every site's Dashboard; visitors are counted by our own `mody-analytics` MU plugin** (decided by the maintainer on 2026-11-11, [tickets/mody-dashboard.md](tickets/mody-dashboard.md)). wp-admin's Dashboard item (same word and icon) opens `admin.php?page=mody-dashboard`, in the Brand page's layout, and core's dashboard redirects there: Overview with the storage, Visitors, Mody's work (messages and tokens, design against configuration, from the `turn` rows), and for members Your sites and Plan & billing (monthly or yearly, the free months left; payments wait for Mollie). `mody-analytics` is the third exception to "platform logic lives in one MU plugin": no cookies, nothing stored in the browser, no address kept. Since 2026-11-12 ([tickets/analytics-journeys.md](tickets/analytics-journeys.md)) every page view of every site is one row of `mody_analytics_views`, under a random visit ID: a daily salted hash maps a visitor to their visit for that day only and is then deleted, so journeys are patterns, never people. Visits are per site and end after 30 minutes without a page; logged-in users count anonymously, bots do not. Views are kept 13 months, then reduced to daily totals. A site's Visitors section reads its own site (journeys, entry and exit pages); Your sites reads all the member's sites together. Since 2026-11-13 each view also carries the visitor's country and city ([tickets/visitor-location.md](tickets/visitor-location.md)), looked up on our own server in DB-IP City Lite (France, CC BY 4.0; `bin/geoip` before a deploy), never the address; a city with fewer than 5 visits in a period is shown only as "Other places in <country>". 1 GB per site (3 GB until 2026-11-13) is enforced with WordPress's upload quota (`Site\Storage`).
- **Take your site with you** (decided by the maintainer on 2026-11-12, [tickets/take-your-site-with-you.md](tickets/take-your-site-with-you.md)): any administrator of a member site downloads the whole site at any time, no questions asked, whatever the plan or billing status: three files (code, media, database). Everything goes but Mody: the code carries Mody Site (the platform's site features as a normal plugin, built from an allowlist by `Export\Portable`), Mody Languages, Mody Images, Spectra, Antispam Bee and the theme, never the agent, the `ai` plugin, the platform's locks, mody-mail, Wordfence or credentials (no password hashes). Builds run in a detached `wp mody-export run` process, at most two at once; files are kept 3 days in `app/dumps/exports/` and served through signed links with Nginx's X-Accel-Redirect.
- **Security pass** (asked by the maintainer on 2026-11-12, [M5-01](tickets/M5-01-hardening-launch.md#security-pass-2026-11-12)): Nginx rules case-insensitive with an allow-list for static files, XML-RPC closed, rate limits on signup, login, lost password, comments and the visitor beacon (`Security\RateLimit`, `Security\ClientAddress`), per-install secrets instead of the committed salts (`Security\Secrets`), no account enumeration, the agent's locks and token budgets (`Agent\Slots`, `Agent\Budget`: a real limit, rule 7; per site, monthly and daily, since 2026-11-13), Spectra's custom JavaScript and unsafe tag names off for members, Delete Site refused until the real flow, the site limit counting owned sites (`mody_owner`).
- **Outgoing mail: the `mody-mail` MU plugin, set only by the environment** (decided by the maintainer on 2026-11-10; WP Mail SMTP, used from 2026-11-09, is gone). `app/web/mu-plugins/mody-mail/` is the only way the platform sends email, and one of the exceptions to "platform logic lives in one MU plugin". It reads `MAIL_SENDER_EMAIL`, `MAIL_SENDER_NAME` and `BREVO_API_KEY` from `.env`; it has no settings screen and stores nothing. Every message leaves from that sender. With the key, `wp_mail()` posts each message to Brevo's API (production); without it, PHP's `mail()` hands it to Mailpit locally, and production fails every message. Libraries for it, if ever needed, go in `app/composer.json`, never in a plugin's own. See [architecture.md](documentation/architecture.md#production) and [M5-02](tickets/M5-02-production-member-sites.md) step 6.
- **Backups: restic to Infomaniak Swiss Backup** (decided by the maintainer on 2026-11-14, [tickets/backups.md](tickets/backups.md); production stays on the laptop at launch). The `backup` service (`config/backup/`, in `compose.prod.yml.sample`) dumps the database every 6 hours, and every night sends the dump, the uploads, the server's `.env` and `compose.prod.yml`, and Nginx Proxy Manager's data to an encrypted restic repository in Switzerland; a copy of the dumps stays on the laptop's internal disk. Ofelia runs it; Uptime Kuma hears every success and failure. `./bin/restore-drill` on the Mac proves a restore.
- **Images: every upload becomes a web-efficient WebP, in the `mody-images` MU plugin** (decided by the maintainer on 2026-11-14, [tickets/image-optimization.md](tickets/image-optimization.md); the fifth exception to "platform logic lives in one MU plugin"). JPEG, PNG and HEIC are replaced before WordPress stores them: upright, at most 2560 pixels on a side (no `-scaled` copy, no original kept), without EXIF, XMP or IPTC (the place a phone writes goes), with the color profile, as WebP (82 for photos, 90 for PNG); the sizes are WebP. WebP and AVIF are changed only above 2560; GIF, SVG and animations never. Imagick on our server, GD otherwise; nothing outside. Core's client-side media processing is off, so the server makes every size. `wp mody-images optimize` converts older media by hand (it rewrites the content's addresses and deletes the old files: back up first). Take your site with you carries it.
- **Production is `mody.cloud` on `home.local`, deployed with `./bin/deploy --env=prod`.** Never copy files to the server by hand, and never edit `.env` or `compose.prod.yml` from the repository. See [architecture.md](documentation/architecture.md#production).
- **Deploy strategy** (decided 2026-11-08): each change goes on its own topic branch (`feature/…`, `fix/…`, `docs/…`). It is merged into `main` locally with `--no-ff`, then `main` is pushed and deployed. Only when the maintainer asks. See [architecture.md](documentation/architecture.md#deploying).
- **Open questions are not decisions.** Check the "Open questions" sections ([architecture.md](documentation/architecture.md#open-questions), [brand-profile.md](documentation/brand-profile.md#open-questions), [membership-tiers.md](documentation/membership-tiers.md#open-questions), [newsletter.md](documentation/newsletter.md#open-questions), [ai-engine.md](documentation/ai-engine.md)) and ask instead of choosing for the team.

## Layout and commands

Core lives in `app/wp`, content in `app/web` (Bedrock-style). Plugins and themes install into `app/web/` through Composer. Layout details: [architecture.md](documentation/architecture.md#repository-layout).

```bash
docker compose up -d                 # start the stack
./bin/wp <wp-cli args>               # WP-CLI in the app container
./bin/composer <args>                # Composer in the app container
./bin/wp theme activate theme        # activate the theme
cd app && composer update --no-install   # regenerate composer.lock on the host
```

`./bin/wp` needs `SITE_SLUG` in `.env` (the sample sets `mody`) and the matching alias in `wp-cli.yml`. First-run steps, all commands and environment variables: [local-development.md](documentation/local-development.md).

## Development rules

- Keep customizations in `app/web/themes/theme`. Keep `functions.php` minimal. Platform logic does not belong in the theme. See [theme-development.md](documentation/theme-development.md#rules).
- Use the theme's named palette colors (`primary`, `secondary`, `accent`, `base`, `contrast`). Never loose hex values in generated content or templates. See [theme-development.md](documentation/theme-development.md#design-tokens).
- Load nothing from third-party CDNs or font services. Serve fonts and assets locally (rule 1).
- Theme text domain is `mody_cloud`. Wrap user-facing PHP strings with WordPress i18n functions.
- Block markup in `templates/` and `parts/` must stay valid serialized blocks. See [ai-engine.md](documentation/ai-engine.md#validation-pipeline).
- Never commit `.env`, `auth.json` or credentials. Production uses `compose.prod.yml.sample` so Xdebug (9003) and MariaDB (3306) are not published. See [architecture.md](documentation/architecture.md#invariants-that-carry-over-from-the-briefing).
- Use the smallest validation that covers the change: `php -l <file>`, a JSON parse of `theme.json`, `docker compose config` (needs a `.env`). See [theme-development.md](documentation/theme-development.md#working-with-the-theme).
- Update the matching file in `documentation/` when behavior or decisions change. Mark guesses as **Open question** or **Inference**.
